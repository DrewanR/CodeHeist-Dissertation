As mentioned in \autoref{sec:methodology/development}, requirements were to be developed in two phases. First, before the start of development, the Core Requirements are created and finalised. These detail requirements of the Core Systems. Following this, after the Core Systems were implemented, the Wider Requirements were to be written. As will be described in \autoref{ch6:results} (TODO: Make more specific), development ended when this would have occurred. As a result, only the Core Requirements will be detailed here.

All the requirements listed here use the MoSCoW requirements system as described by \citet{useCaseModelling-MoSCoW}. For our uses, the \textquote{W} stands for \textquote{Want to have but will not have this time round}, and will be interpreted as not being required but must be possible to be implemented later without significant restructuring or rewriting.

\section{Core Requirements}\label{sec:requirements/core}

The Core Requirement specification, shown in \autoref{tab:coreRequirements/general}, were wrote with the following assumptions about the game:

\begin{enumerate}
    \item The game is in the platformer genre.
    \item The game must contain programming elements.
    \item The Core Systems can be developed isolated from the scenario, and before the level design process.
    \item Non-core systems, such as dialogue, can be implemented later as and when/if they are needed.
\end{enumerate}

\section{Specifying CatCode Requirements DRAFT}

Originally, the plan was to use the Welsh curriculum to create a list of required features, however the curriculum was not prescriptive with content, rather providing more of a guide. This was helpful in providing content for the wider game -- especially progression -- but not here. As a backup, the English curriculum was used, however this feel into a similar problem.

Rather than turning to higher level English requirements such as TODO, we decided to create a list of requirements based on the fundamental building blocks of programming using both our own experience, comparing the documentation (especially keywords) of popular languages such as python, and Scratch's own blocks as a guide. Our main departures from this occurred when providing the tools required to recreate the auto-controlled CatBot, which resulted in the requirement for extra functions such as \texttt{isGrounded()}, \texttt{jump()} and \texttt{isButtonHeld()}.
