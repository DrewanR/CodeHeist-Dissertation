\section{Score Definitions}

When defining scores it was decided that the baseline for success is an getting an average above 75\%, as a result of this, most requirements should be getting an \textquote{unambiguous pass}, with some leeway for \textquote{marginal passes}.

\subsection{Must, Should, and Could Requirements}

\paragraph{Unambiguous pass (3 Points):} A requirement was considered to be unambiguously passes when there was no ambiguity over whether it passed, and the feature was subjectively considered to be high quality. Most of the requirements were binary, so this was common.

\paragraph{Marginal pass (2 Points):} All requirements that were technically fulfilled, had some ambiguity or pass marginally, but did not fall into the above category fell into this one. These were not desired. Subjective requirements were more likely to fall into this category due to the harsh evaluation.

\paragraph{Failure, with possible future implementation (1 Point):} This category was reserved for marginally failures or failures that could be corrected in the future. Possible future implementation was defined as being possible if the feature could be added without significant restructuring of the codebase or effort. If there was any significant doubt over the plausibility of future implementation, it would fall into the next category.

\paragraph{Failure, without easy future implementation (0 points):} This was the category that requirements fell into if non of the above categories were true.

\subsection{Won't Requirements}

It was understood early on that \textquote{Won't} requirements may be implemented at a later date, hence why consideration was given to these. To prevent these getting implemented too soon, no credit was given if they were fulfilled beyond the 3 points for future implementation.

\paragraph{Trivial future implementation (3 Points):} This score was given if it was clear immediately how the feature would be implemented and this process would not require any significant new systems or restructuring.

\paragraph{Possible future implementation (2 Points):} This score was given if it was somewhat clear how a feature would be added in the future, but it may take longer or require minor rewriting or new systems to be added.

\paragraph{Unknown (1 Point):} This was a catch-all for features were it was not clear how they would be added in the future but it was not likely to fall into the next category

\paragraph{Impossible to implement in the future (0 Points):} This scores was given if it was suspected that the specified feature would not be possible to implement in the future without significant restructuring of existing systems. When in doubt, 1 point was rewarded instead of this category.
